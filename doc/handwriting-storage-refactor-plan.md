# 手写笔记存储与同步重构

实现日期：2026-10-20。改动仅在客户端；未修改 Cloud、Builder，未部署。

范围：修复整篇 JSON 单字段覆盖造成的笔迹丢失，保留旧笔记、图片、PDF、文字框、形状、列表、WebView、源文件导入导出与复制。按用户要求，不兼容旧客户端继续编辑新格式。

## 实际采用的结构

继续使用现有 RocksDB、Yrs、Collab WebSocket 和 `CollabType::Document`，不引入另一套数据库或迁移服务器。

```text
Collab 根 data（已有 Y.Map）
  document                         原有 Document 根，保持不变
  data.sbn2_data                   旧 base64 JSON，保留原始字节，后续保存不再覆盖
  handwriting_schema = "2"
  hw2:["doc",字段]                  文档属性
  hw2:[集合,实体ID,字段]             页面、笔迹、图片等实体的属性
  hw2:["pages",页面ID,"backgroundImage",属性]  PDF 引用/几何分别合并
  hw2:["deleted",集合,实体ID,代次]    删除标记
  hw2:["restored",集合,实体ID,代次]   显式撤销删除
```

每条记录是现有 Y.Map 的一个独立键，值为该属性的 JSON。读取时以旧 JSON 为基础叠加记录，重新投影为画布已认识的 JSON。新笔记不需要旧快照。

没有建立新的共享嵌套 Map：多端独立创建同名 Y.Map 会竞争并隐藏其中一方的子记录，直接使用已有根 Map 避开这一问题。新客户端也可以离线编辑旧笔记，不要求先获得服务端迁移锁。

旧页面、笔迹缺少 ID 时，按 viewId、旧页序、集合名和旧元素序生成确定性 UUID v5；相同内容的两笔仍有不同 ID。新页面、笔迹使用随机 UUID；原有 WebView 保留整数 ID，新增 WebView 使用 UUID 派生的 52 位随机整数，避免离线两端自增 ID 冲突；页面复制和源文件导入重新分配全部实体 ID。实体顺序使用可插入的十六进制排序键，同键按 ID 排序。

## 保存、恢复及远端更新

FFI 保存请求新增编辑基准 `base_sbn2_bytes`、账号和工作区；响应新增本次本地提交的规范快照。Rust 只写“编辑基准 → 本机快照”的差异，不把提交前刚收到的远端实体当成本机删除，也不把未显示的远端变更混进下一次本机基准。

同一数据服务内保存串行，后一笔使用前一笔成功提交的基准，保证连续编辑/撤销能提交反向改动。失败不推进基准；重新打开时重放待提交日志。旧客户端没有这些请求字段，因此必须更新。

本地保存顺序：

1. 原子写入 `.pending`，保留本次基准、下一快照及固定账号/工作区。
2. 原子写入完整 `.sbn2`（含已有本地图片字节）。保留首次旧文件 `.legacy` 和上一版 `.previous`。
3. 提交 Rust 实体差异，并显式刷入已有 RocksDB。
4. 成功后删除待提交日志；失败保留完整本地副本与日志。

原子写采用同目录临时文件、flush 和 rename；同一路径写入串行。主备份损坏时尝试 `.previous`、`.legacy`，不删除损坏原件。读取云端失败且没有有效本地内容时禁止以新空笔记替代；成功加载的普通 Document 缺少手写命名空间时才初始化。

Rust 缓存按账号、工作区、viewId 隔离。异步保存、打开、附件回写在关键等待点检查身份，防止切换账号/工作区后向错误目标写入。页面异步读取和资源回填还检查 viewId 与文档代次。

远端通知在初始化同步前订阅；UI 在落笔、输入、保存期间延后应用。仍解析完整快照，但复用内容未变化的页面对象和 notifier，保留这些页面的撤销记录。发生远端变化的页面清理其撤销记录，页结构操作的旧历史也不跨远端重载复用。

删除记录不自动回收。迟到的旧修改不能复活删除；观察到删除后的显式撤销只恢复已观察到的删除代次，不能抵消另一次尚未观察到的删除。

## 图片和 PDF

- 保留历史 `imageBytes`、`imageBase64`、`imageUrl`、SVG 以及原有 PDF JSON 字段和 URL 的读取方式；旧 JSON 字节不被重写。
- 完整本地备份继续包含图片字节，精简云快照沿用现有序列化约定：已有 URL 时只提交 URL；尚未上传的图片仍允许内嵌字节，保证离线恢复。
- 附件任务读取固定文档的本地文件，不持有 Widget。任务按路径合并，运行期间的新保存会触发下一轮处理。
- 上传显式指定工作区，以内容 SHA-256 命名；同一 PDF 的多页共享上传结果。
- `.assets` 持久保存已上传 URL，`.assets.pending` 保留待处理记录。后续上传或引用提交失败不会丢掉先前上传结果；重开/保存笔记会重试。部分附件成功时先提交已成功的引用。
- 上传完成通过带基准的差异提交回写引用；PDF 地址和目标矩形等属性独立合并，不覆盖并发变换。
- PDF 导入原件存入 `pdf_cache/originals/`，不参与 LRU。LRU 仅淘汰新格式、可重新下载的缓存；旧未知来源文件保留。
- 新 PDF 缓存键包含完整 URL 路径的 SHA-256，避免不同工作区同名文件串用；临时 URL 查询参数不影响缓存键。旧文件名缓存继续可读，迁移复制不删除旧副本。
- `.ponynhw` 保持现有 ZIP/main.sbn2/assets 格式。每次导入使用独立资源目录，避免 `pdf_0.pdf` 覆盖其他笔记。导出补齐图片字节、优先利用本地 PDF；资源不可取得时返回错误，避免生成缺附件的源文件。
- 页面重建与复制保留图片、PDF、文字框、Quill 数据、形状及扩展字段，避免修改文字/笔迹时丢掉同页附件。

Flutter：37 个测试通过（另执行 4 个组级初始化/清理），涵盖旧数据兼容、页面复制、串行保存及撤销、离线失败重开、损坏备份恢复、账号/工作区切换、附件上传重试与持久去重测试；扩展已有 PDF 重开/缓存测试，覆盖 URL 重名隔离、旧缓存读取、原件免于 LRU。

验证环境的限制：

- 标准 Flutter 测试器需要本地端口，当前沙箱禁止绑定端口。使用相同测试源，通过 Flutter frontend_server 编译，再直接在 flutter_tester 中运行 test_api 测试组；保留 setUp/tearDown、分组及 testWidgets 执行。
- 缓存中的 Collab 依赖构建脚本会写入只读源码目录。Rust 检查使用相同版本依赖的可写临时副本，并复用已有 target；仓库中的依赖版本和路径未改动。
- 静态分析没有 error，仍有原有 warning 和样式级 info；不能称为无诊断通过。
- 未启动完整客户端、未连接真实云端做双设备端到端测试，未接触生产用户数据。

## 明确保留的限制

- Flutter → Rust 目前仍提交快照再计算差异，编辑器端序列化开销仍与笔记大小有关；网络同步和 Yrs 存储已不再覆盖整篇 JSON。大笔记性能优化后续可改为工具级增量事件，不必更换存储模型。
- 同一实体同一属性同时修改由 Yrs 决胜；同一文字框内容没有字符级合并。这里只兼容代码中已有的文字内容，不新增文字编辑功能。
- UI 仍按变化页面重建，变化页面的旧撤销记录会清理；没有承诺跨设备操作级撤销。
- 附件失败任务在该笔记再次打开或保存时重试；没有新增全应用常驻重试调度器。
- “Rust 保存成功”表示已本机持久化并交给现有同步插件，不等同于服务器持久化确认；本轮没有新增云端确认协议。
- 不自动删除旧快照、旧附件、删除标记和历史冲突副本。旧客户端继续写旧字段不受支持；发布时应要求更新。
